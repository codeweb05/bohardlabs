# Theming

## Why the table looks different in your app

Short answer: it does not. Your theme does.

The package hardcodes no colour, no font, no radius and no cell padding. Headers, borders,
hover states, the toolbar, the chips and the pager all read tokens from the active MUI theme:
`primary.main`, `divider`, `text.secondary`, `action.hover`, `shape.borderRadius`,
`typography.fontFamily`.

That means a table dropped into an app with heavy MUI overrides looks like that app, and the
same table in a Storybook running stock `createTheme()` looks like stock MUI. Same component,
same props, different host.

The usual sources of the difference, in order of how much they change:

| Theme override                       | What moves                                                     |
| ------------------------------------ | -------------------------------------------------------------- |
| `palette.primary`                    | sort arrows, active filter chips, selection, the bulk bar      |
| `palette.divider`                    | the container's border, and every cell rule                    |
| `palette.action.hover` / `.selected` | row hover, a checked row, a row being edited, the detail panel |
| `palette.background.paper`           | the table's own surface, and the sticky header behind it       |
| `typography.fontFamily`              | every string in the table                                      |
| `shape.borderRadius`                 | the container, the toolbar controls, the chips                 |
| `MuiTableCell.styleOverrides.head`   | the header's tint, colour, font, letter spacing and rule       |
| `MuiTableCell.styleOverrides.root`   | the cell rule, its weight and its style, and the body font     |
| `MuiButton`, `MuiIconButton`         | every control in the toolbar, the bulk bar and the pager       |
| `MuiOutlinedInput`                   | the search field and every filter input                        |
| `MuiChip`                            | the active-filter chips and anything a `cell` renders as one   |
| `MuiPaper` (`elevation8`)            | the column popover, the filter panel and the row action menu   |

Pick any preset other than the two stock ones in the theme toolbar above to see it. The six
are each a plain `createTheme` call, and the difference between them is not only the palette:
Tokyo Night is square and monospaced with hard 1px rules, Catppuccin Latte has no row rules
at all and puts everything on a soft shadow, Solarized Light is serif on warm paper with
dashed hairlines, High contrast is 2px black on white. Every story repaints under all of
them, and the package's source does not change.

### What a theme cannot move

Four things look like theme levers and are not. Row height, cell padding and body font size
come from `density`; header capitalisation comes from `headerCase`. The table sets all four
through its own `sx`, and `sx` wins over `styleOverrides`, so a theme that sets `padding` or
`textTransform` on `MuiTableCell` changes nothing and reads like a bug when someone later
tries to work out why. Set them with the props: the **Density scale** and **Header casing**
stories show every value of each.

Where the table scrolls is also a prop rather than a theme choice. Without `maxHeight` the
table has no height of its own and the page scrolls; with it, the table scrolls and
`stickyHeader` has something to stick to. The **Scroll containment** story has both.

## Matching a host app

Do it in the theme, not in props. A theme override applies to every table in the app at once,
and to the MUI components around it, so the page stays consistent:

```tsx
const theme = createTheme({
  palette: {
    primary: {main: '#00695f'},
    divider: '#cfe0dd',
    action: {hover: 'rgba(0, 105, 95, 0.08)', selected: 'rgba(0, 105, 95, 0.16)'},
  },
  shape: {borderRadius: 8},
  components: {
    MuiTableCell: {
      styleOverrides: {
        head: {
          backgroundColor: '#eef4f3',
          color: '#0f3b36',
          letterSpacing: '0.06em',
          borderBottom: '2px solid #cfe0dd',
        },
      },
    },
  },
});
```

## Per-table escapes

For the one table that has to differ:

- **`containerSx`** styles the wrapper, and takes the MUI `sx` shorthand, so it can reach the
  parts inside through selectors.
- **`getRowSx(row)`** styles a row from its data, which is how a status colour or a
  struck-through cancelled row is done. It is a function of the record, so it stays correct
  when the rows change.
- **`density`** and `enableDensityToggle` change row height, padding and font size together,
  so a compact table stays readable rather than only shorter.
- **`headerCase`** decides whether headers are capitalised (the default) or printed as
  written. Set it to `none` for acronyms and product names.
- **`cell`** on a column renders anything. That is where a chip, an avatar or a link goes.

What is not there on purpose: a `classNames` prop, a colour prop, a style token API. Each one
would be a second, weaker theme sitting next to the real one.

## Dark mode

Nothing to do. The table reads the palette, so a theme with `mode: 'dark'` is enough. Switch
to Nord, Dracula or Tokyo Night in the toolbar to check your own cell renderers: a hardcoded
`#fff` in a custom `cell` is the usual thing that breaks, and it will be in your code rather
than in the table. Dracula is the fastest at finding one, being the most saturated.

## Accessibility and colour

The a11y addon runs on every story here with `test: 'error'`, so a contrast regression fails
the build rather than showing up in a panel. If you tint headers or rows, keep body text at
4.5:1 against its own background. MUI's filled palette chips are the common failure at small
sizes, which is why the stories use outlined ones.
